# 细粒度知识归属标注指南 v1

> 对应论文 5.2 节 / 实施计划 M3。标注对象：**作者 × 方法 × 角色** 四元组的参与关联 Z。
> 标注界面：`python pipeline/annotation_server.py --serve` 后访问 http://localhost:8765/?who=A（标注员 B 用 ?who=B）

## 1. 标注任务

对每篇论文，界面给出：论文标题、摘要、Methods 全文（折叠）、每个候选方法实体的原文上下文（高亮），以及「作者 × 方法」判定矩阵。

对每个单元格做三态判定：

- **是（1）**：有文本证据支持该作者参与了该方法的相关工作；
- **否（0）**：证据表明该工作由其他人完成，或该作者仅挂名且无任何相关证据；
- **不确定（2）**：文本证据不足以判断。

判定为「是」的单元格，需进一步勾选该作者**以什么角色**参与（候选列表只含该作者在本文中声明过的 CRediT 角色）。

## 2. 判定依据（按优先级）

1. **贡献声明 / 作者贡献脚注**：最直接证据（界面中作者的声明角色列）；
2. **Methods 正文中的分工表述**：如 "X.Y. implemented the model…"、"performed by …"等；
3. **致谢与补充材料**：提到某人负责某项分析/实验；
4. **作者专长先验**（慎用）：仅当以上都没有时，可依据作者在该领域的已知方向做弱推断，此时建议标「不确定」而非「是」。

## 3. 判定规则与边界案例

| 情形 | 判定 |
|---|---|
| 作者声明了 Methodology，论文只有一个方法 | 「是」+ 勾选 Methodology |
| 作者声明 Methodology，论文有 3 个方法，无法确定哪个 | 对每个可能的方法标「不确定」，不猜 |
| 通讯作者只声明 Supervision / Funding | 方法格子一律「否」（除非正文另有证据） |
| 「是」但角色无法细分 | 标「是」+ 勾选最可能的一个角色即可 |
| 方法实体本身是背景提及（reviewed） | 所有作者标「否」（未参与该方法的实际工作） |
| 多人共同承担同一方法 | 每人都可标「是」，**不要求互斥** |

## 4. 质量控制

- 两名标注员独立标注同一批论文，**过程中不得交流具体判定**；
- 不允许查看任何模型输出或 LLM 锚点（界面已不包含此类信息）；
- 先完成 5 篇校准批（W8 试点），比对分歧后再进入正式标注；
- 一致性指标：Cohen's κ（目标 ≥ 0.7）；分歧样本集中协商裁决，裁决记录附在数据中。

## 5. 工作量参考

- 每篇约 50 个判定单元，预计 5–10 分钟/篇；
- 试点批 50 篇 × 2 人 ≈ 每人 4–8 小时，可分多次完成（界面自动记录进度）。
